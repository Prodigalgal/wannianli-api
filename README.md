# 万年历 API

一个只返回当前 UTC+08:00 时间结果的传统万年历 HTTP API。工程使用 Java 25、Spring Boot 4.1，历法与黄历算法均在本项目内实现，不依赖任何 Java 农历/黄历库，也不需要数据库、缓存、消息队列等中间件。

## 运行

环境要求：Java 25。仓库包含 Gradle Wrapper。

```powershell
.\gradlew.bat test
.\gradlew.bat bootRun
```

访问唯一业务接口：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v1/almanac/current
```

接口没有日期或时区参数。每次请求都通过注入的 `Clock` 获取当前时刻，再强制转换到固定偏移 `UTC+08:00`；不依赖上海、北京等地域时区数据库。

## 返回内容

- 当前 UTC+08:00 时间、公历日期、星期、儒略日数
- 农历年/月/日、闰月、大小月、月朔时刻
- 年柱、月柱、日柱、时柱、生肖、四柱纳音
- 当前节气区间、前后节气、季节、三伏、两种古籍数九口径
- 建除十二神、黄黑道十二值神（两套体系独立计算）
- 吉神、凶煞、彭祖百忌、冲煞、胎神、二十八宿
- 最终宜、忌、宜忌并存清单

公开 JSON 使用中文键名，只返回上述结果，不混入文献、免责说明、证据等级或规则轨迹。后台审计模型仍保留每个活动的裁决轨迹、每条命中规则的原始宜忌、证据等级和出处，并由测试验证引用闭合性。

所有公开布尔值统一为中文字符串“是”或“否”，不输出裸 `true` / `false`。

## 自研历算

历算层没有日期查表，也没有第三方历法实现：

1. 以 TT 时间尺度计算太阳视黄经和真朔，再用 Delta T 换算 UT。
2. 以中国标准时间中包含朔的民用日为初一。
3. 冬至所在月为十一月；两个冬至月之间有十三个月时，首个无中气月为闰月。
4. 年柱在立春精确时刻切换，月柱在十二个“节”切换。
5. 日柱由公历日的连续儒略日数推导；时柱由日干和双小时辰推导。
6. 建除、十二值神、三煞、德神、冲煞、纳音等均由本地公式或版本化古籍表计算。

2020 年闰四月揭示了一个重要边界：夏至和下一朔落在同一中国民用日时，中气属于新月。实现按民用日期区间判断，而不是错误地按两个天文瞬间的先后顺序归月。

## 宜忌消解

主规则来自《钦定协纪辨方书》卷十。引擎先保留各规则原始输出，再应用卷中明确的逐月制化专例，最后才使用六等总表：

| 等级 | 有德神 | 无德神 |
|---|---|---|
| 上 | 从宜不从忌 | 从宜不从忌 |
| 上次 | 从宜不从忌 | 宜忌并存 |
| 中 | 从宜不从忌 | 从忌不从宜 |
| 中次 | 宜忌并存 | 从忌不从宜 |
| 下 | 从忌不从宜 | 诸事皆忌 |
| 最下 | 诸事皆忌 | 诸事皆忌 |

古籍专例优先于通用六等表。例如“辰戌丑未月满日与德神并”仍保留军事与求医疗病六项禁忌，不能因日等为上而消除。

《玉匣记》系统的彭祖百忌和胎神属于较低证据层。彭祖规则只补充《协纪辨方书》没有裁定的活动，不能覆盖官修主规则。证据层级和冲突轨迹保留在后台审计模型中，不进入公开 JSON。

## 权威边界

- `GB/T 33661-2017` 是农历编算规范，不是吉神凶煞或择吉规范。
- 《钦定协纪辨方书》是本项目择吉主干，电子转录仍需以武英殿刻本或四库影印本继续校勘。
- 《御定星历考原》用于三伏；《五行大义》《三命通会》《李虚中命书》用于纳音及四柱交气口径。
- 数九在古籍中有冬至次日和冬至当日两种传统，API 同时返回，不伪造唯一答案。
- 《钦定协纪辨方书》明确承认二十八宿绝对起元年月不可考。后台计算使用公开的现代通行锚点，并在审计模型中将该值标为 `D_CONVENTIONAL_ANCHOR`。
- 胎神占方未在已核对的《协纪辨方书》正文中找到，故在审计模型中标为《玉匣记》通书系统的 `C_TRADITIONAL_TRANSMISSION`。

详细文献与采用边界见 [docs/REFERENCES.md](docs/REFERENCES.md)。传统神煞及宜忌仅用于文化信息展示，不构成科学、医疗、法律或投资建议。
