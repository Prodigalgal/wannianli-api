# 万年历 API

一个按 UTC+08:00 计算当前或指定公历/农历日期时间的传统万年历 HTTP API。工程使用 Java 25、Spring Boot 4.1，历法与黄历算法均在本项目内实现，不依赖任何 Java 农历/黄历库，也不需要数据库、外部缓存或消息队列。

新增 v2 语义接口与只读 MCP，保留 v1 兼容。推荐新调用方使用 `GET /api/v2/almanac?date=2026-08-03&time=12:30:15` 或 POST 同路径，字段为 `calendar/date/time/leapMonth`；当前时刻用 `/api/v2/almanac/now`。区间用 `/api/v2/almanac/range?startDate=2026-10-01&endDate=2026-10-14`，含首尾最多14天、按天计入共享配额。v2 使用英文程序字段、原生布尔值及明确的 `dateTime`，每份结果带核心子集 `scope`。支持范围见 `/api/v2/almanac/capabilities`，OpenAPI 3.1 描述见 `/api/v2/almanac/openapi.json`。详见 [v2接口文档](docs/API_V2.md) 与 [MCP接入](docs/MCP.md)。

## 运行

环境要求：Java 25。仓库包含 Gradle Wrapper。

```powershell
.\gradlew.bat test
.\gradlew.bat bootRun
```

获取当前时刻：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v1/almanac/current
```

`GET /api/v1/almanac/current` 通过注入的 `Clock` 获取当前时刻。新增 `POST /api/v1/almanac/calculate` 接受公历或农历年月日时分秒，例如：

```json
{"历法":"农历","年":2020,"月":4,"日":1,"时":12,"分":30,"秒":15,"是否闰月":"是"}
```

时分秒可省略（默认零），是否闰月默认“否”。两接口均固定 `UTC+08:00`，不接受时区或查询参数。详细字段、示例、错误码及安全限制见 [接口文档](docs/API.md)。线上2.5.0已双端发布，每端60项公网检查及两代MCP客户端验证通过，见[发布记录](docs/DEPLOYMENT_2026-10-23_V250.md)。本轮核定气往亡、反支、分至、月忌日并实现，另复核三伏正确，见[本批核定](docs/CALENDAR_DAY_RULES.md)；包含此前2.4.0补10项月神。原图核验累计160页，现以电子文本批量核对、原图裁决疑点，见[文字来源](docs/ELECTRONIC_TEXTS.md)。Worker默认Python urllib仍有Cloudflare 1010限制，局部规则权限待补，见[兼容性](docs/CLOUDFLARE_API_COMPATIBILITY.md)与[待办](docs/TODO.md)。

## 返回内容

- 当前 UTC+08:00 时间、公历日期、星期、儒略日数
- 农历年/月/日、闰月、大小月、月朔时刻
- 年柱、月柱、日柱、时柱、生肖、四柱纳音及各柱所属旬、旬空
- 当前节气区间、前后节气、季节、三伏、两种古籍数九口径
- 建除十二神、黄黑道十二值神（两套体系独立计算）
- 吉神、凶煞、彭祖百忌、冲煞、胎神、二十八宿
- 最终宜、忌、宜忌并存清单

v1 公开 JSON 使用中文键名，只返回上述结果，不混入文献、免责说明、证据等级或规则轨迹。后台审计模型仍保留每个活动的裁决轨迹、每条命中规则的原始宜忌、证据等级和出处，并由测试验证引用闭合性。

v1 布尔语义仍为中文字符串“是”或“否”；v2 与 MCP 使用原生 `true` / `false`。

## 自研历算

全书底本校勘采用批量分页索引和规则族交叉核查。26册3521扫描页的索引、转录缺口及检索命令见[全书索引](docs/CLASSICAL_INDEX.md)，执行与验收条件见[校勘流程](docs/CLASSICAL_WORKFLOW.md)。资料缓存、转录草稿、影像核验、算法实现和部署分别计数。

历算层没有日期查表，不依赖第三方历法运行库。天文系数与章动公式的来源、许可和生成器均保留：

1. 以 IMCCE 发布的完整 VSOP87D 地球黄经和日地距离系数，加入源自ERFA的106项IAU1980章动、光行差和FK5修正后求节气；真朔采用Meeus周期项，再用Delta T换算UT。天文模块仍为近似模型，毫秒输出不代表毫秒精度。
2. 以中国标准时间中包含朔的民用日为初一。
3. 冬至所在月为十一月；两个冬至月之间有十三个月时，首个无中气月为闰月。
4. 年柱在立春精确时刻切换，月柱在十二个“节”切换。
5. 日柱由公历日的连续儒略日数推导；时柱由日干和双小时辰推导。
6. 旬空由每柱六十甲子序号所属的十日旬，以及该旬未覆盖的两个地支直接推导。
7. 建除、十二值神、三煞、德神、冲煞、纳音等均由本地公式或版本化古籍表计算。

实现统一按 UTC+08:00 民用日期归属朔和中气，而不是错误地只比较天文瞬间先后。这同时覆盖 2020 闰四月以及 2014-12-22 冬至与朔同一民用日的边界；跨冬至区间还显式保留末端十一月，避免 2026-12-09 一类日期落出月份区间。

## 宜忌消解

主规则来自《钦定协纪辨方书》卷十。引擎保留原始输出，优先应用已核定专例。原书六等总则如下；原表两页的11列、132个月份起例已独立转录并核对现有35组逐月条件，详见[原表核验](docs/SOURCE_GRADE_TABLE.md)。原表未列的日子不能由空格猜为中等，专忌与铺注另判：

| 等级 | 有德神 | 无德神 |
|---|---|---|
| 上 | 从宜不从忌 | 从宜不从忌 |
| 上次 | 从宜不从忌 | 宜忌并存 |
| 中 | 从宜不从忌 | 从忌不从宜 |
| 中次 | 宜忌并存 | 从忌不从宜 |
| 下 | 从忌不从宜 | 诸事皆忌 |
| 最下 | 诸事皆忌 | 诸事皆忌 |

古籍专例优先于通用六等表。例如“辰戌丑未月满日与天德、月德或其合神并”仍保留军事与求医疗病六项禁忌；寅申巳亥月闭日或辰戌丑未月平日叠月煞，无四德时诸事皆忌；酉日固定忌宴会且不注宜庆赐赏贺；申月戌日满才兼天狗，并非所有满日都有天狗。

原实现曾将整数权重相加，与这里的文献声明不符；本轮审计已删除权重字段及阈值分级。只对已核定组合返回相应日等，其余返回“未定”，双向冲突列入“宜忌并存”。月破忌目即使遇德神仍保留，不能批量翻为宜。收日只有与月恩、四相或时德同现才新增“修仓库”，执、危、收日的伐木、畋猎、取鱼按相应节令区间处理。

《玉匣记》转录中的彭祖百忌属于较低证据层，只补充《协纪辨方书》没有裁定的活动，不能覆盖官修主规则。六十甲子胎神方位表另列为近现代通书传承，不再错误归入《玉匣记》原文。证据层级和冲突轨迹保留在后台审计模型中，不进入公开 JSON。

## 权威边界

- `GB/T 33661-2017` 是农历编算规范，不是吉神凶煞或择吉规范。
- 《钦定协纪辨方书》是本项目择吉主干，电子转录仍需以武英殿刻本或四库影印本继续校勘。
- 《御定星历考原》用于三伏；《五行大义》《三命通会》《李虚中命书》用于纳音及四柱交气口径；《增删卜易》旬空章和《钦定古今图书集成》六甲孤虚法用于旬空。
- 数九在古籍中有冬至次日和冬至当日两种传统，API 同时返回，不伪造唯一答案。
- 《钦定协纪辨方书》明确承认二十八宿绝对起元年月不可考。后台计算使用公开的现代通行锚点，并在审计模型中将该值标为 `D_CONVENTIONAL_ANCHOR`。
- 胎神占方未在已核对的《协纪辨方书》正文及当前《玉匣记》转录中找到完整六十日方位表，故另以 `FETAL_GOD_TRADITION` 标为 `C_TRADITIONAL_TRANSMISSION`，不宣称为古籍唯一结论。

详细文献与采用边界见 [docs/REFERENCES.md](docs/REFERENCES.md)。传统神煞及宜忌仅用于文化信息展示，不构成科学、医疗、法律或投资建议。

“吉神”“凶煞”是已校勘核心子集。此前披露的卷五日神缺项、卷十第二批逐月条件及宣政改布政等铺注已补入；无禄按年/月/太阳条件动态判断，并只铺注原文明列的十二类。六等原表已取得影像并核对，不代表全书其他神煞及所有联动均已覆盖。未实现不表示原典没有该神煞。当前范围、来源及回归结果见[原表核验](docs/SOURCE_GRADE_TABLE.md)、[第四轮工作记录](docs/FOURTH_AUDIT.md)与[待办状态](docs/TODO.md)，历史逐条裁决见[算法审计](docs/ALGORITHM_AUDIT.md)。
