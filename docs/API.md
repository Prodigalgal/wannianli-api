# 公历/农历计算 API

本文描述保留兼容的 **v1**。新调用方可使用标准日期、GET查询、英文程序字段与原生布尔值的 [v2](API_V2.md)，AI客户端可接入 [MCP](MCP.md)。v1中文键与“是/否”约定保持不变。

**兼容性变更记录（2026-10-22）**：前一轮已将十二值神原输出“天德”改为原书区分名“宝光”。这是公开值枚举的破坏性变更，旧调用方应更新字符串匹配；天德吉神的名称仍为“天德”。本轮补齐部分神煞和逐月条件，也会修改对应日期的神煞、宜忌结果，详见[二审核验](SECOND_AUDIT.md)。

第三轮补充开日铺注：破土、安葬、启攒不注宜；原来仅因开日而列入“忌”的条目改为不注，其他未解除的独立禁忌仍可使其留在“忌”中。因此部分日期的上述活动会从“忌”列表消失，不表示转为“宜”。例如2020-02-02不再注忌安葬、启攒，但破土因土王用事等专忌仍保留。详见[第三轮核验](THIRD_AUDIT.md)。

**2.3.0规则扩展（2026-10-23）**：新增临日、驿马、天后、天马、兵吉、五富、天仓及九个祭祀类月神。v1、v2、MCP的吉神和宜忌清单均可能增加条目，含“安神”“修祠宇”等卷十原活动名；指定会合与其他专忌继续共同裁决。JSON字段结构、德神判定及日等规则保持既有契约。消费方应允许神名和活动名子集扩充，详细原叶、作者撤回旧说及黄金用例见[逐页校勘](SOURCE_COLLATION.md)。

2026-10-23继续补第二批逐月条件、卷五日神和阴阳专日。无禄按年/月及太阳填实、会合动态判断，癸亥保留；按“止注”只输出祭祀、解除等指定十二类，其余不铺注，但内部忌证据不删除。2024-01-18因此不再公开列出远行忌，巳日原始禁忌仍保留；非无禄的2024-03-06仍列忌远行，月德合原有的遣使推荐被独立互注规则抑制。此类省略不表示转为宜。太阳模型改用完整VSOP87D黄经/日地距离及106项章动，1979大寒由01-21改归01-20，交节时刻及衍生属性也随之调整。详见[第四轮工作记录](FOURTH_AUDIT.md)。

当前实现已于2026-10-23发布并通过公网验证，详见[发布记录](DEPLOYMENT_2026-10-23_V221.md)。Java与独立Worker使用同一请求格式、固定UTC+08:00，支持对应公历日期 **1801-01-01 至 2199-12-31**。

## 接口与请求

| 方法及路径 | 含义 |
|---|---|
| GET /api/v1/almanac/current | 获取服务器当前时刻的结果 |
| HEAD /api/v1/almanac/current | 仅返回响应头 |
| POST /api/v1/almanac/calculate | 计算指定公历或农历日期时间 |

线上基础地址：[Java服务](https://wannianli.mnnu.eu.org)、[独立Worker](https://wannianli-worker.mnnu.eu.org)。例如计算接口为 `https://wannianli.mnnu.eu.org/api/v1/almanac/calculate`，使用POST及以下JSON格式。

Worker 的根路径 `/` 保持当前时刻接口；Java 的部署反向代理原有根路径转发不变。接口不接受查询参数。

POST 必须为 UTF-8 `application/json`，只接受一个扁平对象：

| 中文字段 | 类型 | 要求 |
|---|---|---|
| 历法 | 字符串 | 必填，只能为“公历”或“农历” |
| 年 | 整数 | 公历1801—2199；农历1800—2199，且转换后的公历仍在支持区间 |
| 月 | 整数 | 1—12 |
| 日 | 整数 | 公历按实际月份校验；农历按实际大小月校验，不接受不存在的三十日 |
| 时 | 整数 | 可省略，默认0；范围0—23 |
| 分、秒 | 整数 | 可分别省略，默认0；范围0—59，不接受闰秒60 |
| 是否闰月 | 字符串 | 可省略，默认“否”；只能为“是”或“否”，公历不能为“是” |

农历1800年只为支持公历1801年春节前日期；不存在的闰月及越界转换均返回400。公历2月30日、1900年2月29日等直接拒绝，不自动滚动日期。

不接受字符串数字、小数、指数写法、布尔值、null、数组、嵌套、未知字段、重复字段（包括转义后重名）。

## 调用示例

公历：

```powershell
$payload = @{ 历法='公历'; 年=2026; 月=8; 日=3; 时=12; 分=30; 秒=15 } | ConvertTo-Json -Compress
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/almanac/calculate' -Method Post `
  -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
```

农历闰四月：

```json
{"历法":"农历","年":2020,"月":4,"日":1,"时":23,"分":59,"秒":59,"是否闰月":"是"}
```

对应公历2020-05-23 23:59:59+08:00。未指定时分秒时按当天00:00:00计算。

## 返回与口径

成功返回200，保持原接口的中文结果结构：公历、农历、四柱、旬空、节气、三伏、数九、神煞、宜忌等。为兼容现有结构，顶层“当前时间”在 calculate 接口中表示**本次提交的计算时刻**。公历和农历输入只要解析为同一时刻，结果相同。

生肖随立春年柱换年，日柱在民用午夜换日（晚子时不提前换日）；时分秒会影响交节前后的年柱、月柱及季节。农历初一按包含朔的整个民用日归属，不在朔的瞬间切换日号。

“节气第几天”从前一交节所在日期起含首日计数；“距下个节气天数”按民用日期差。因此当天尚未交节时，可能同时为“第16天”和“距下个节气0天”，没有承诺每一节气固定15天。

“吉神”“凶煞”仅为已实现子集；“日等”可能为“未定”。裁剪范围、文献版本与未来日期不确定性见 [算法审计](ALGORITHM_AUDIT.md)。后台保留证据和裁决轨迹，公开 JSON 不混入审计信息。

## 错误和资源保护

| 状态码 | 情况 |
|---|---|
| 400 | 日期、字段、类型、UTF-8、JSON结构或查询参数不合法 |
| 404 / 405 | 路径或方法不在白名单；405附Allow |
| 408 | 请求体读取超时 |
| 413 | 请求体超过1024字节（也检查未知长度和分块流） |
| 415 | 非JSON、非UTF-8声明或压缩请求体 |
| 431 | 请求头过大；Java由Tomcat协议层执行8KB上限 |
| 429 / 503 | 请求过于频繁、计算并发已满或Worker缺少限流绑定 |
| 500 | 内部计算异常，公开响应不含堆栈、路径或内部异常细节 |

应用层错误体示例：`{"错误":"公历日期不存在"}`。协议层拒绝的格式由Tomcat或Cloudflare决定。

Java默认每实例令牌桶突发20、每分钟补充120、并发4。可用 `almanac.security.requests-per-minute`、`burst`、`max-concurrent` 调整。限制不按客户端自报IP分桶，伪造 `X-Forwarded-For` 不会绕过配额。重启、多实例各有独立桶。Worker本地桶相同，并使用固定业务键的原生共享限流；该原生限流按Cloudflare位置近似计数，并非全球严格限制。[平台说明](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

Worker流读取总超时5秒。Java采用单调时钟检查5秒读取预算，并配置Tomcat连接/读取超时5秒；阻塞读取必须由连接层超时唤醒，不能将预算检查误解为精确的中断式总截止时间。Java还限制连接数256、工作线程32、排队64、吞弃请求体1KB，禁用multipart及转发头自动解析。

结果和错误均设置no-store、nosniff、禁止嵌框、CSP和Referrer-Policy；不开放CORS。服务是公开、无状态的历算API，没有账号权限、数据库、任意路径读写、执行脚本或回源URL输入。客户端输入不会拼入SQL、命令或HTML。本轮已发布应用保护和Worker原生限流绑定，并验证公网的参数、重复字段、请求体大小、方法、路径和安全响应头；未进行流量压力攻击或完整公网渗透测试。网络层TLS、WAF、DDoS和全局严格配额仍属于部署设施，本轮未调整DNS、TLS或主机防火墙。
