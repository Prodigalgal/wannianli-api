# 气往亡、反支、分至与月忌日核定

日期：2026-10-23；计算描述版本2.5.0。本批按电子正文核定四类历日规则，已同步接入Java、Worker及其共用API/MCP契约。未增加原图核验页数，原有160页仍是影像核验累计值；电子文本核定和新增索引均不计为影像核验。

## 采用来源与取舍

起例使用[Kanripo固定修订卷六](https://github.com/kanripo/KR3g0051/blob/8b5522eb0299afbd575f1cb556e972c71c40c42a/KR3g0051_006.txt)67b—69a、72b—76a，最终活动范围以[卷十同修订](https://github.com/kanripo/KR3g0051/blob/8b5522eb0299afbd575f1cb556e972c71c40c42a/KR3g0051_010.txt)63b—64a、69a—71a及74b互注为准。交叉核对已有维基文库[卷六修订787343](https://zh.wikisource.org/w/index.php?oldid=787343)和[卷十修订787351](https://zh.wikisource.org/w/index.php?oldid=787351)快照；同一传本的电子转录一致不充作独立古本证据。

| 核定对象 | 起例 | 最终用途与边界 |
|---|---|---|
| 气往亡 | 从交节所在民用日含首日计数：立春7、惊蛰14、清明21、立夏8、芒种16、小暑24、立秋9、白露18、寒露27、立冬10、大雪20、小寒30 | 与月支往亡分开；卷十同列21项专忌，德合赦愿并犹忌；不恢复作者删去的施恩封拜旧忌 |
| 反支 | 本月朔日地支：戌亥→初一、申酉→初二、午未→初三、辰巳→初四、寅卯→初五、子丑→初六 | 忌上册进表章、陈词讼，遇一般德神仍保留；不把卷六推测性的婚姻、纳财象义扩成禁忌 |
| 分至 | 春分、夏至、秋分、冬至交节所在UTC+08:00民用日全天 | 22项活动“不注”，冬至另不注伐木；同时省略公开宜、忌和宜忌并存，保留后台原始证据 |
| 月忌日 | 农历每月初五、十四、廿三，闰月按实际月朔独立计日 | 采用卷十最终“止注”十二类：祭祀、宴会、沐浴、整容、剃头、整手足甲、求医、疗病、补垣、扫舍宇、修饰垣墙、平治道涂；不沿用卷六多列的破屋、坏垣 |

气往亡与月支往亡在卷十同列用途，故宜宣政事遇气往亡也按互注改为布政事；只转移原推荐及其他独立证据，不把气往亡自身宣政事忌复制到布政事。既有八个德赦愿会合专例的裁决顺序保持原状，不把它们泛化为普通“有德神”解忌。

“不注”是输出铺注政策：它不删除月破、专忌等原始命中，不把活动改为宜，也不重算六等。月忌所列十二类仍按各自证据判宜、忌或并存，不能把白名单理解为十二项全宜。分至与月忌重叠时，两项省略条件共同生效；也继续遵守既有无禄止注。

## 可见行为变化

- 2020-04-24为上等且有德神、只有气往亡而非月支往亡，21项专忌仍保留；原宣政事推荐改列布政事。
- 2026-02-17为戌日朔且有德神，反支的上册进表章、陈词讼仍忌。
- 2024-03-20春分的嫁娶有原始宜证据，2024-12-21冬至的嫁娶有原始忌证据，两者均按“不注”省略；冬至伐木另行省略。
- 2024-01-04为农历廿三，安床、开仓库的原始忌证据仍在，但公开不再铺注。此前第二轮用它验证一般德神不会覆盖从忌，现改用同样满足条件且非月忌的2024-01-17继续检验该性质。
- 2020-07-25安葬的逐月专忌仍保存在审计中，因月忌不公开铺注；2026-02-10月忌与气往亡同日，求医在十二类内仍忌，上册进表章则省略。

JSON字段结构与schemaVersion=2.0保持原有约定。凶煞列表可新增气往亡、反支、月忌日及当天分至名称；其中分至、月忌是铺注标签，名称个数不代表数值强度。v2每次结果的scope及capabilities.annotationPolicies公开说明省略范围；v1消费者见[兼容性记录](API.md)。

## 独立预期与验证

生产规则存于[rules/calendar-days.json](../src/main/resources/rules/calendar-days.json)；[测试预期](../src/test/resources/fixtures/calendar-days.json)独立抄录，不从生产表生成。覆盖2026年12个气往亡日期及前后日、12种受控朔支×7天、2020与2024全年732个民用日、闰四月三个月忌日、四个分至全天及前后日，以及有德/上等与专忌的叠加。

月破和逐月专忌旧回归继续要求原始忌证据存在、不能翻成宜；只有独立源文预期能说明的月忌/分至省略才允许不出现在公开忌列表。不是把旧失败断言一律放宽为“非宜即可”。新增公开铺注政策的两端断言，约束API披露与独立活动表一致。

## 顺带核定：三伏的含交节日边界

[卷十二10b](https://github.com/kanripo/KR3g0051/blob/8b5522eb0299afbd575f1cb556e972c71c40c42a/KR3g0051_012.txt)明确：夏至逢庚即计初庚，立秋逢庚即末伏。逐读Java/Worker现有计庚循环均从交节民用日开始，符合条文，保留原算法。

按当前天文模型扫描1801—2199年798个夏至/立秋交节日，其中夏至逢庚39例、立秋逢庚41例。对80例运行Worker实际公开计算：前者初伏为夏至后第20日、再10日入中伏，后者当天入末伏，边界与前日断言全部通过。报告存于`build/validation/sanfu-source-review.json`；这是对古籍计数边界的核定，不是对未来交节日期作外部观测认证，也不把这80例另计为Java测试数。

## 构建依赖的实际告警

首轮CI安装依赖提示4项high，官方npm审计确认来自Wrangler 4.118.0经miniflare引入的sharp/undici链；不是本批历法代码新增的HTTP入口。核对[undici维护者公告](https://github.com/nodejs/undici/security/advisories/GHSA-rfgv-xxqx-mfg5)与[sharp维护者公告](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w)，更新精确锁定的Wrangler至4.152.0，保留两代MCP SDK版本。官方registry安装及再次审计均为0项已知漏洞；本地打包和差分复验通过，工具链更新后的远程CI另行登记。

两个workflow均加入明确的官方registry审计，高危及以上会失败，避免仅打印告警仍继续通过。此举覆盖构建/开发依赖，不等同线上完整渗透测试，也不宣称不存在未知漏洞。本地默认镜像不支持security audit端点，因此审计按单条命令指定官方registry，未改用户全局配置。
