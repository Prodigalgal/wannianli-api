## 检索按规则族合并读

```sh
node tools/search-classical-sources.mjs "游祸" --volumes 6,10,11,12,13,36 --context 1
node tools/search-classical-sources.mjs "不注" --volumes 10 --context 1
node tools/search-classical-sources.mjs "搬移" --volumes 10,11 --context 1
node tools/search-classical-sources.mjs --family VOLUME06_REMAINDER --limit 100 --json
```

普通多个关键词采用“全部命中”，规则族采用族内任一关键词命中。检索对明确列出的简繁异体字、搬移/般移做有限归并，不是完整通用简繁转换。显示上限1—500；相邻上下文0—3个转录片段，可重复定位后读完整章节，不能把默认一页上下文当作全文结论。

每次检索标明原叶码、来源行、转录身份、相邻片段、限制或会合候选标签，以及扫描链接的身份：

- `VERIFIED_LEAF_LINK`：来自人工台账已核对的扫描页和叶码。它只证明定位依据，不保证该页每字或每个体系已核定。
- `CANDIDATE_NOT_VERIFIED`：由同卷已知锚点的线性偏移推测，不能当作核验记录；遇不同偏移即停止该卷的自动推测。
- 重复叶码：保留每一次出现及独立ID；不自动选择其中一次，不建立确定的扫描页链接。
- 空转录或无对应片段：回看影像。卷十72b原表即没有对应文本片段，不能拿73a代替它。

工作队列见[计划](sources/classical-review-plan.json)及[自动定位结果](sources/classical-review-queue.json)。每个关键词仅列前12个命中，另给总数及截断标记；完整定位使用检索命令。队列“待核”不表示这些条目全部未实现，必须先核对现有算法。

## 一条规则的交付单元

围绕同一神煞或规则族连读卷三至八的起例、卷十的宜忌、卷十一至十三的用事/公规及卷三十六的辨讹。每条记录至少包含：来源册ID、扫描页和原叶码、图片哈希、原文采用段、前引旧说是否被驳、标准化起例、活动名称、会合条件、除外条件、实现位置与黄金用例。

先独立记录原文与预期结果，再与实现对照。二次复核重新看原图，尤其检查干支、否定、顺逆、添/替换、与某神并/与任意吉神并。作者否定的引文保留为“未采用”，不以第一次出现的用途直接入库。

每个规则族先做定向验证；该批完成后统一跑完整Java/Worker测试与公开契约差分，随后构建和发布。资料采集、索引和检索工具的更新只需验证离线重建、来源身份、异常处理及既有回归，不为索引变化重新部署生产计算服务。

## 图表与全文缺口

先补卷十四及现有空转录中的表格定位，再核定年/月/日表的推算口径。规则确定后程序逐格对比，把不符单元、边界、旁注及未识别单元列为复核任务；不能用少量抽样声明全表通过。当前还没有实现全书表格识别和逐格比对，也没有完成全书逐字校勘。

CI离线检查来源快照、分页完整性、重复叶码保留、未核页身份及生成文件是否过期。检索也检查来源指纹及分页索引哈希，台账或来源改变后须先重建，不能继续输出过期的确定链接。需要变更上游版次时，先更新来源锁与差异记录，再重新核对相关影像和黄金用例。
