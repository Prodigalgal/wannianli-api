# 第三轮外部审计核验

本页保留2026-10-22的阶段记录。当前实现范围、后续天文修正与有界区间见[第四轮工作记录](FOURTH_AUDIT.md)，待办见[状态表](TODO.md)。

本文件记录项目对用户提供审计意见的复核和处置，不是审计方签发的独立报告。

| 意见 | 核验 | 处置 |
|---|---|---|
| Worker源码“完全独立”措辞过强 | 成立。classical.js与semantic.js在构建时读取Java资源目录中的共享JSON；单独worker目录不能构建 | 两个README明确“共享数据、运行独立”，列出完整仓库要求和构建时内联机制；保留既有路径，避免无必要的数据搬迁 |
| 新增v1字段可能触发v2 fail-closed错误 | 成立。这是未同步契约时的风险，当前字段映射没有缺口 | Java和Worker测试递归收集真实公开v1响应全部字段，要求与contract.fieldNames键集完全相等；四个布尔字段也要求完全覆盖。Worker另验证新增未映射嵌套字段会被拒绝 |
| v2中文日等与英文程序键不一致 | 作为易用性改进成立；直接替换已发布值会破坏兼容 | 保留activities.dayGrade中文值，新增dayGradeCode稳定英文枚举，capabilities.dayGrades给出七值对照；OpenAPI和MCP输出Schema同步更新 |
| HEAD已支持却未写入OpenAPI | 成立 | 为四个GET路径逐项补HEAD操作，保留GET参数、独立operationId，所有状态明确无响应体；两端真实请求验证 |

根响应19个字段，递归共有76个不同字段名。覆盖测试不仅验证当前已有映射，还能在以后增加、删除或改名公开字段时阻止契约静默漂移。映射层继续保留运行时fail-closed保护，测试不取代运行时检查。

API描述和MCP服务软件版本更新为2.1.0；结果结构版本仍为2.0，因为本轮仅添加字段。调用方应忽略未使用的扩展字段，使用dayGradeCode进行判断，使用dayGrade显示传统中文名。

本轮没有根据“降低未定比例”目标猜测更多等第。卷十建、除、定、执、危、成及破日细分列入下一批逐条校勘，须有原文条件、冲突优先级和黄金用例后再启用；复杂铺注仍按capabilities列出的缺项披露。区间/批量接口继续待产品需求明确，并须预先限定日期范围、体积和计算配额。

本次也补上第二轮收尾发现的开日丧葬铺注与明确“余不忌”组合处理：开日不注宜破土、安葬、启攒，只有其他未获解除的禁忌来源存在时才注忌；不忌仍不自动生成宜。具体证据与回归说明见[第二轮核验](SECOND_AUDIT.md)。
